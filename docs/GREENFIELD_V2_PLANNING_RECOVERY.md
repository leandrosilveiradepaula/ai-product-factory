# Recuperação V2 do planejamento de greenfield já desenvolvido

Incidente real Dark Channel Studio: jornada c43e7781-7cb9-49fd-8459-cc358880df0a, run 1ed3c5d1-fc2a-4bab-a4a9-12f53bc83c29, SHA Studio 55e8e8d8422ee044eb1112ab678cb0223e987742. [Execução original](https://github.com/leandrosilveiradepaula/ai-product-factory/actions/runs/45618026690): discovery e specification persistidos, planning sem tarefas/decisões. A origem do pedido é o comentário OWNER 7162981651. O histórico anterior não autoriza reabertura.

A jornada V2 vinculada a greenfield executava discovery/specification/planning sem consultar o código atual; a rotina de retomada exigia reconciliation/gap_analysis e excluía esse formato. Este candidato prepara inspeção limitada e exclusivamente no SHA imutável, incluindo amostra real de entrypoints/testes e governança para pedidos amplos de greenfield. Inventário não autoriza escrita, não comprova qualidade/release e não substitui os limites dos agentes. Projetos existentes continuam com inspeção explícita.

O checkpoint conserva as etapas concluídas e cria, no máximo, uma run de planning vinculada à mesma jornada, task, geração, digest e source SHA. Rejeita etapa incompleta, resposta vazia sem recibo, candidato/filhos/Change Set e concorrência. Nenhuma nova autorização de custo, acesso, migration de produto ou merge. Gates de execução e orçamento permanecem ativos.

**Candidato**: QA PostgreSQL isolada e testes de unidade obrigatórios; a migration deve ser versionada pelo CLI, revisada e instalada somente após merge humano e autorização explícita do Control Plane. O CI do rascunho gera o arquivo por CLI oficial com digest fixo. A Factory deve retomar a jornada legítima existente após instalação, sem novo Start e sem repetir Discovery ou especificação. Não declarar o produto pronto até prova independente.
